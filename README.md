# Narrative - Software Engineering and Design Enhancement

This artifact is an enhanced version of the Event Calendar application originally developed as the final project for CS-360: Mobile Architecture and Programming. The original application was created in 2024 and was designed as a mobile calendar system that allowed users to create, view, and update scheduled events. The enhanced version expands upon the original implementation through improvements to the application’s user interface, event visualization system, and overall software structure. Most notably, the enhancement introduces a redesigned Monthly View capable of displaying multiple events per day as well as a new Daily View that provides detailed visualization and interaction with time-based event data.

I selected this artifact because it demonstrates several important software development skills, including user interface design, software architecture improvement, and the application of structured event-handling logic within a mobile application environment. For example, although the original project already contained a functional event management system and database structure, its interface design did not properly support the underlying data model because only a single event could be displayed per day. Therefore, in preparation for the code review process, I implemented several improvements that extended beyond the scope of the original enhancement proposal. In the original iteration of the application, the user interface was only capable of displaying a single event per day. As an intermediate improvement, I redesigned the lower event display section into a scrollable event list that dynamically displayed all events associated with the selected date in chronological order based on each event’s start time. While this revision improved event accessibility and resolved the limitation of hidden events, it also introduced several usability concerns. Most notably, the event list occupied a significant amount of screen space even when no events were scheduled for the selected day. Additionally, because only a single event preview remained visible within the Monthly View itself, the interface still did not clearly communicate when multiple events existed on a given date. Therefore, as part of this artifact enhancement, I redesigned the Monthly View to directly display multiple events within each calendar cell rather than relying exclusively on a secondary event list. Events are now displayed in chronological order within the calendar itself, with overflow handling used when the number of scheduled events exceeds the available display space. This redesign more effectively aligns the interface with the underlying event data model while improving usability, visual clarity, and overall scalability. Additionally, this artifact introduced the development of a dedicated Daily View to support more detailed event interaction and visualization. While the redesigned Monthly View provides a high-level overview of scheduled events, the Daily View allows users to interact with event data within a structured 24-hour timeline where events are displayed according to their scheduled start times, enabling users to more clearly interpret time-based relationships between events. This layered interface design separates high-level event browsing from detailed event management, resulting in a more modular and scalable user experience. Ultimately, these improvements showcase my ability to evaluate an existing software system, identify design limitations, and implement scalable solutions that improve both usability and maintainability.

Because these enhancements were modeled closely after those described in my original enhancement plan, they successfully met the course outcomes identified in said plan. More specifically, the redesigned Monthly View and newly implemented Daily View demonstrate my ability to design and evaluate computing solutions by identifying limitations within the original system and implementing a more scalable and user-focused interface structure. These enhancements also demonstrate my ability to apply software development techniques and tools to create a functional solution that improves overall system usability, maintainability, and scalability. Through the introduction of layered event visualization and overflow handling, the application now more effectively supports real-world calendar management expectations while providing clearer and more organized interaction with event data. At this time, I do not anticipate any major updates to my original outcome-coverage plans, as the completed enhancement aligned closely with the objectives established in the initial proposal.

Through the enhancement process, I developed a stronger understanding of how software architecture and user interface design must work together to support scalable functionality. One of the most important lessons learned involved the importance of separating data management from presentation logic. Although the original application’s database structure was capable of storing multiple events per day, the interface design prevented users from effectively interacting with that data. Initial interface improvements implemented during preparation for the code review partially addressed this limitation. However, the redesign of the Monthly View and the implementation of the Daily View during this artifact provided a more complete and scalable solution. These redesigns also simplified portions of the application’s underlying implementation. Prior to the enhancement, events were displayed through a dedicated event list positioned beneath the calendar, which required the use of a separate EventAdapter class to manage event rendering and interaction. By integrating event visualization directly into the calendar views themselves, this additional intermediary structure was no longer necessary. As a result, the revised design improved not only the user experience, but also the maintainability and reusability of the application’s codebase. This process reinforced how limitations in software design can negatively impact both usability and overall software architecture.

The primary challenge encountered during this enhancement involved translating the identified design improvements into functional implementation within the existing codebase. While the proposed enhancements were conceptually clear, integrating them into an already established application required careful consideration of how existing components interacted with one another. This process benefited from preparation for the code review, which involved re-familiarizing myself with the original codebase to better understand existing event handling and user interface logic. Ultimately, this highlighted the complexity of working with pre-existing systems, where changes in one area can have unintended effects on other parts of the application. Although the implementation of this artifact’s enhancements was relatively straightforward once the system was fully understood, the initial effort required to rees
tablish a clear mental model of the application represented the most significant challenge. Overall, this experience reinforced the importance of maintainable code structure and clear separation of concerns, as these factors directly impact the ease of future development and modification.



# Narrative - Algorithms and Data Structure Enhancement

For my algorithm enhancement, I implemented an algorithm that detects overlapping events during event creation or editing and provides a warning to the user, accordingly. The user then has the option of either adjusting the event times and dates or proceed with saving the event despite the overlap. 

Notably, these enhancements conflict with my initial enhancement highlighted during my original enhancement plan. In my original plan, I intended to enhance the Daily View by implementing an interval partitioning algorithm to visually display events spanning from their start to end times within a vertical timeline. However, after further consideration and initial implementation planning, I realized that this approach introduces some practical usability limitations. In particular, when multiple events overlap significantly, the available horizontal space becomes constrained, which can negatively impact readability and make individual events difficult to interact with or modify. Ironically, this original plan was meant to showcase my ability to employ strategies for building collaborative environments that enable diverse audiences to support organizational decision-making. The idea being that, by making events easier to represent visually, more people would benefit from the application. However, considering its ability to hinder the user experience, this enhancement was unable to showcase my ability to meet this outcome. 

While my alternative approach still applies structured interval comparison logic, it focuses on detecting scheduling conflicts and providing users with meaningful feedback during event creation and modification. By integrating conflict detection directly into the event management workflow, the enhancement improves decision-making and system usability without introducing unnecessary interface complexity. This provides a clear and distinct example of my ability to design and evaluate computing solutions that solve a given problem using algorithmic principles and computer science practices and standards appropriate to its solution, while managing the trade-offs involved in design choices. The conflict-detection enhancement also demonstrates my ability to apply well-founded computing techniques to solve a practical scheduling problem. By implementing temporal comparison logic that identifies overlapping events and presenting users with contextual warnings, I improved the application's ability to support informed decision making while increasing its overall reliability and usability. Therefore, this enhancement reflects the application of appropriate software development tools and techniques to deliver functionality commonly found in professional calendar and scheduling systems. Furthermore, this enhancement also showcases my ability to improve communication between the application and its users by providing clear and timely notifications when scheduling conflicts occur, allowing users to make informed decisions regarding event creation. 

Through the enhancement process, I developed a greater appreciation for the importance of balancing technical functionality with overall user experience. While my original enhancement proposal focused on implementing interval partitioning to visually represent overlapping events within the Daily View, further evaluation revealed that the approach introduced usability concerns that could negatively affect readability and user interaction. As a result, I gained further experience in understanding that technically sophisticated solutions are not always the most effective if they create additional challenges for the end user. # Narrative - Databases

This artifact is an enhanced version of the Event Calendar application originally developed as the final project for CS-360: Mobile Architecture and Programming. The original application was created in 2024 and was designed as a mobile calendar system that allowed users to create, view, and update scheduled events. To enable these features, as well as provide support for multiple user accounts, the application used an SQLite database. Although SQLite provided a lightweight and reliable solution for local data storage, it had several limitations when applied to a more scalable, multi-user system.
I selected this artifact because it provided an opportunity to improve both the functionality and security of the application's database architecture. Most notably, because SQLite is a file-based local storage system, the application's data was tied directly to a single device. As a result, uninstalling or resetting the application could lead to complete data loss, reducing reliability across multiple devices. To address these limitations, the application was altered to use Firebase Firestore, a cloud-based database solution. These changes also made future enhancements, such as email-triggered event updates, significantly easier to implement. This alteration also reduced the application’s exposure to traditional SQL injection vulnerabilities by replacing SQL-based queries with Firestore's document-based data model.

Further improvements were made through the implementation of Firebase Authentication. In the original application, user passwords were stored directly within the SQLite database, creating a security risk if the database were compromised. Firebase Authentication removed the need to store passwords within the application's database by delegating credential management to Firebase's authentication infrastructure. As a result, unauthorized access to the database would not directly expose user passwords. Together, Firebase Firestore and Firebase Authentication demonstrate my ability to develop systems with a security-focused mindset through the use of modern cloud technologies, authentication services, and rule-based access control.
The migration from a localized SQLite database to Firebase Firestore also improved the application's ability to support collaboration and information sharing. Because data is now stored within a centralized cloud database rather than on a single device, authorized users can access the same information across multiple devices. This creates a more collaborative environment by improving the availability and consistency of data used for decision-making. Furthermore, this enhancement also demonstrates my ability to use well-founded and innovative tools and techniques to implement solutions that deliver value and support industry-specific goals. After all, Firebase Firestore and Firebase Authentication are modern, industry-standard cloud-based technologies that improve the applications’ security, scalability, and accessibility.

Throughout this enhancement process, I learned how to integrate and utilize the cloud-based services offered by Firebase Firestore and Firebase Authentication within an Android application. This experience expanded my understanding of cloud-based data storage and highlighted the differences between managing data locally through SQLite and remotely through a cloud database. Because I had no prior experience with Firebase technologies, there was a significant learning curve associated with understanding their architecture and implementation requirements. One challenge involved handling date and time information. During previous enhancements, the application had been modified to use LocalDate and LocalTime objects. However, Firebase Firestore does not natively support these data types. Therefore, date and time values had to be converted between multiple formats before being stored and retrieved. Resolving the resulting formatting and compatibility issues required extensive testing and debugging. Despite these challenges, the enhancement strengthened my understanding of cloud-based application development while also improving my problem-solving and debugging skills.
